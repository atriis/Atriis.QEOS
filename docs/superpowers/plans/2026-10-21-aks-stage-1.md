# AKS Stage 1 (staging that works) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** QEOS runs on an AKS staging cluster from images in ACR, deployed by one Helm chart, with Flexible Server, Azure Blob, Key Vault secrets and email, while the Compose path keeps working unchanged.

**Architecture:** Domain-free and Azure-free work comes first and is proven on every push by installing the chart into a kind cluster in CI. Shared code changes are opt-in by environment variables whose defaults keep today's Compose behaviour. Azure-specific pieces (Blob store, Bicep, deploy workflow) come last.

**Tech Stack:** Docker (nginx-unprivileged, python:3.11-slim), Helm 3, kind, Gateway API (AKS Application Routing), cert-manager, Bicep, GitHub Actions (OIDC to Azure), Trivy, azure-storage-blob + azure-identity, FastAPI/Python, React/Vite.

**Spec:** `docs/superpowers/specs/2026-10-21-aks-deployment-design.md` (Stage 1 = section 5.11 item 1)

## Global Constraints

- The Compose path (local stack, tunnel, CI's compose jobs, `deploy/` single VM) must keep working with no `.env` change: every new setting defaults to today's behaviour.
- No secret in a Helm values file, ConfigMap, image layer or log line. Secrets arrive as Key Vault files (CSI) or Kubernetes Secrets.
- Every container runs as non-root, with `allowPrivilegeEscalation: false`, all capabilities dropped and a read-only root filesystem (writable emptyDirs only where listed).
- Kubernetes Service names equal the Compose service names; nginx upstreams use `<name>${UPSTREAM_SUFFIX}` where `UPSTREAM_SUFFIX` is empty on Compose and `.<namespace>.svc.cluster.local` on Kubernetes.
- Gateway: 2 replicas on AKS; its rate-limit rates are values, halved on AKS (`auth` 5→3 r/s, `api` 20→10, `collect` 10→5, `collect_blobs` 50→25, `collect_artifacts` 10→5; Compose keeps today's).
- APIs and dashboard: 2 replicas; loop jobs: 1 replica; PodDisruptionBudget `minAvailable: 1` on every 2-replica Deployment.
- Images: `<acr>/qeos/<svc>:<git-sha>` for every master commit; `:<version>` added on `platform-v*` tags. Trivy fails the build on a fixable CRITICAL.
- Storage selector `ARTIFACTS_BACKEND`: `s3` (default) or `azure`.
- Migrations: one Helm `pre-install,pre-upgrade` hook Job; migrations must stay compatible with the previous release (expand/contract).
- Commit with `git commit -o <paths>`; never `git add` a directory, `git add -A`, `git reset`; push only an explicit SHA after the CI-equivalent gate. Every commit updates the affected .md files.

## Review Focus

1. Compose regressions: a compose up with today's `.env` must still pass CI's compose smoke and gateway jobs. Test: CI unchanged and green in every task that touches shared files (Tasks 1–4).
2. A failing migration on `helm upgrade`: the release fails, old pods keep serving, and no new pod starts. Test: the kind job installs once, then upgrades with a deliberately broken migration image tag and asserts the old ReplicaSet still serves (Task 6).
3. Secrets leaking into rendered manifests: `helm template` output must contain no secret value. Test: a chart test greps every values file's rendered output for the CI dummy secret strings (Task 5).
4. An nginx upstream that resolves on Compose but not on Kubernetes (or the reverse). Test: render the template with both suffixes and run `nginx -t`; the kind smoke hits every route prefix (Tasks 3, 6).
5. The dashboard with no `config.js` (Compose, older images): SSO buttons keep using the build-time values. Test in Task 2.
